# 多语言层（i18n）

给 Multiversal Warrior 加的多语言支持。核心目标只有一个：**同步上游更新时零冲突**。

## 为什么这么做

游戏是纯前端页面，所有文案最终都会落成 DOM 文本节点（没有 canvas 绘制）。
所以这里采用「运行时替换」而不是「改源码」：

```
上游源码 (index.html / fullRevamp.js)  ← 一个字都没改
        │
        ▼  浏览器渲染
      DOM 树
        │
        ▼  i18n.js 拦截文本节点与属性，按词典替换
   中文 / 英文界面
```

`index.html` 里只多了 3 行（一个 `<link>` + 两个 `<script>`），集中在 `<head>` 末尾。
即使上游改了整个游戏逻辑，`git pull` 也不会和汉化产生冲突——需要维护的只有
`i18n/locales/*.js` 这些词条文件。

## 目录

```
i18n/
├── i18n.js            # 引擎：文本节点拦截、MutationObserver 增量翻译、语言切换
├── i18n.css           # 中文排版微调（窄按钮不换行等），可自由改
├── locales/
│   └── zh-CN.js       # 简体中文词条（words + patterns）
└── _build/            # 工具产物（候选清单、未翻译明细、截图），不提交
saves/
└── graduation.json    # 毕业存档：全资源拉满、界面全解锁，用于覆盖率自检
tools/
├── i18n-extract.mjs   # 从源码抽取候选文案，对比词典算缺口
├── i18n-check.mjs     # 无头浏览器渲染真实页面，列出界面上仍是英文的文本
├── i18n-probe.mjs     # CDP 探针：执行任意 JS、抓控制台错误、截图
├── make-save.mjs      # 生成毕业存档（把一份普通存档改造成全解锁）
├── i18n-tour.mjs      # 注入毕业存档 → 点开全部页签 → 输出未翻译清单
└── i18n-fragments.mjs # 静态碎片扫描：从源码模板字符串还原「真实文本节点」逐条比对
userscript/
└── mw-i18n-helper.user.js  # 油猴脚本：游戏内快进 + 边玩边收集漏翻（见 userscript/README.md）
```

## 使用

启动一个静态服务器（ES module 需要 http，不能直接双击打开）：

```bash
python -m http.server 8123
# 打开 http://127.0.0.1:8123/index.html
```

- 左下角有 `EN / 中文` 切换按钮，选择会记在 `localStorage`（键名 `mw.i18n.lang`）。
- 想分享固定语言版本的链接：`index.html?lang=zh-CN`
- 想收集未翻译文本：`index.html?i18nDebug=1`，玩一会儿后在控制台执行
  `I18N.exportMissing()` 会下载一个 JSON。

控制台 API：

| 调用 | 作用 |
| --- | --- |
| `I18N.setLang('zh-CN')` | 切换语言（`'en'` 为原文） |
| `I18N.getLang()` | 当前语言 |
| `I18N.stats()` | 已翻译节点数、未命中数、轮次等 |
| `I18N.collectMissing(true)` | 开始记录未翻译文本 |
| `I18N.getMissing()` / `I18N.exportMissing()` | 取回未翻译清单（后者直接下载） |
| `I18N.t('Power')` | 取单条译文，未命中返回原文 |

## 词条怎么写

`locales/zh-CN.js` 里有两块：

**words** —— 整段文本精确匹配。空格会被归一化，但大小写、标点必须和原文一致。
游戏原文混用了全角/半角括号（例如 `Iron Golem × （`），遇到时按原样录入。

**patterns** —— 数值会变、或者被 `<span>` 切碎的文案。按数组顺序匹配，先具体后笼统：

```js
p(/^Tier (\d+)\/(\d+)$/, '层级 $1/$2')        // 用 $1 引用捕获组
p(/^(.+?) (×[\d.]+) \($/, '%1 $2（')          // 用 %1 表示「先查词条再替换」
```

`%n` 是本项目的小扩展：游戏里很多标签被拆成
`<div>Golem damage ×2 (<span>5.0</span>)</div>`，文本节点只剩 `Golem damage ×2 (`，
用 `%1` 就能把 `Golem damage` 单独翻出来，同时保住后面的数字样式。

`%n` 是**递归**的（深度上限 4），所以组合式标签能自动拆解：

```
Woodcutter price /2 (   →   %1价格 /$2（   →   伐木者价格 /2（
                          ↑ %1 = "Woodcutter" 再查一次词条
```

两个容易踩的点：

- **模式顺序即优先级**。通用规则（如 `^(.+?) max level \+(\d+) \($`）必须排在
  专用规则（`^Upgrade ([\d,\s-]+) max level ...$`）之后，否则专用规则永远轮不到。
  新增词条时如果发现「只翻译了一半」，九成是顺序问题。
- **游戏原文混用全角/半角括号**。`Woodcutter price /2（` 和 `... /2 (` 是两条不同的
  文本，必要时两种都要写。

## 毕业存档自检

后期内容（土/风/金之树、地狱三阶、药水装备）用新档根本走不到，靠人工玩到那里再截图
不现实。所以做了「造一个满级存档 → 自动点遍所有页签 → 扫残留英文」的流程：

```bash
node tools/make-save.mjs          # 用 i18n/_build/save-raw.json 生成 saves/graduation.json
node tools/i18n-tour.mjs          # 注入存档 + 巡检 + 双重校验
```

`make-save.mjs` 的改造方式（都可以自己加）：

| 项目 | 处理 |
| --- | --- |
| 资源 | 白名单字段拉满（不能无脑遍历，`*R`/`*Size` 这类是结构字段，放大会让游戏按 1e40 个格子循环） |
| 五棵树 | 每个节点 `active/unlocked=true`、`level=10` |
| 挑战者 | 等级 500；训练等级 100 |
| 子系统 | 远征 `level=1`（矿场解锁条件）、宝物 `active`、熔炉/矿场 `unlocked` |
| 背包 | 预置 8×20 网格（正常游戏是玩家首次拖动才逐格创建，直接跳到后期会每帧报错） |

巡检工具会输出两份结果：

- `收集器`：`I18N.getMissing()` 记录的未翻译文本（引擎侧视角）
- `DOM 残留`：直接扫页面，找翻译后仍含拉丁字母的文本节点（UI 侧视角）

两者互补——碎片被「部分翻译」（例如只替换了括号）时收集器不会报警，但残留扫描能抓到。

### 三种检查方式各自漏什么

| 方式 | 能看到 | 看不到 |
| --- | --- | --- |
| `i18n-tour.mjs` 运行时巡检 | 真实渲染出来的界面 | 需要「先拥有实物」才显示的内容 |
| `i18n-tour.mjs` DOM 残留扫描 | 部分翻译的半截文案 | 同上 |
| `i18n-fragments.mjs` 静态扫描 | 源码里所有模板字符串的文本节点 | 运行时才拼接出来的字符串 |

**装备 / 宝物 / 药水的名字**只有静态扫描能发现：毕业存档里没有这些物品，
相关列表根本不渲染，运行时两种检查都是 0 漏翻的假象。
所以每次改词条后，三个都跑一遍：

```bash
node tools/i18n-fragments.mjs   # 静态（约 1 秒）
node tools/i18n-check.mjs       # 新档首屏（约 20 秒）
node tools/i18n-tour.mjs        # 满级档全页签（约 90 秒）
```

最近的巡检结果（1100 条词条 / 178 条模式）：

```
静态扫描：1 条（LeftLife，是源码里的变量名，误报）
新档首屏：3 条（">" 箭头、语言切换按钮、开发占位 "test"）
满级档：收集器 0 条，DOM 残留 7 条（6 条 log 公式 + "test"），异常 0
```

## 同步上游的流程

```bash
git pull origin main            # 拿到新版本

node tools/i18n-extract.mjs     # 1. 看新增了哪些文案（会打印尚缺 N 条）
node tools/i18n-extract.mjs --missing

node tools/i18n-check.mjs       # 2. 渲染真实页面，列出界面上仍是英文的文本
node tools/i18n-check.mjs --todo    #    直接输出可粘贴进词典的空词条
```

正常情况只需补 `locales/zh-CN.js`，永远不用碰 `index.html` / `fullRevamp.js`。

如果某个版本游戏大改（换渲染方式、换框架），这套 DOM 层会失效。届时才需要考虑
把词条注入到源码层——那份改动就要单独维护一个 patch 分支了。

## 已知限制

- **数字记数法后缀不翻译**：`Dc`、`Oe`、`Qa` 这类是数值简写（10^33 之类），属于玩法惯例，保留原样。
- **浏览器原生控件**：`<input type="file">` 的「选择文件 / 未选择文件」由浏览器渲染，不受页面控制；
  中文系统的浏览器会显示中文。
- **性能代价**：游戏每帧用 `innerHTML` 重写数值面板，我们改写后游戏认为内容变了，
  于是又会重写一次，形成「写英文 → 翻中文」的循环。实测 1280×800 下仍是 61 FPS，
  开销约每秒千余次文本替换。如果以后出现卡顿，可以把 `i18n.js` 里
  `flush()` 的 10ms 预算调小，或改用 `I18N.stop()` 暂时关闭。
- **覆盖率**：用毕业存档跑完 26 个页签后，收集器为 0，DOM 残留只剩 6 条 `log(...)`
  数学公式（保留 ASCII 更清楚）和 1 处开发占位 `test`。
  成就列表因为需要真实达成记录，毕业存档也伪造不出来，属于唯一还需要真人补的部分。
- **`test` 字符**：页面某处有一个开发遗留的 `test` 文本节点，源码里搜不到字面量，
  可能是 SVG 或图片 alt，不影响游玩，没动它。
